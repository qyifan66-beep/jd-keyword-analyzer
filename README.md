# JD 词频分析器

用「多 Agent 工作流 + Python 交叉验证」完成招聘市场关键词分析与简历缺口诊断。

## 项目背景

校招求职时需要回答两个问题："市场要什么"与"我的简历缺什么"。本项目汇集 8-9 份目标岗位的结构化 JD 画像（B 端销售 / FAE / 渠道 / 整合营销 / GTM 等方向），用 AI 工具链完成词频统计与简历缺口诊断，并以"可验证"的方式对比不同实现路径的结果质量。

## 核心设计决策

**能用代码的环节绝不上模型。** 词频统计是确定性任务，LLM 计数会产生幻觉——因此统计放在代码节点，LLM 只做它擅长的两件事：非结构化→结构化（提取）、结构化→叙事（报告）。每个 LLM 节点都有输出 Schema 约束 + 低温设置，抑制提取漂移。

## 双版本实现与交叉验证

| 版本 | 实现 | 说明 |
|---|---|---|
| v1 脚本版 | Python 标准库（零依赖），人工词典 + 同义词合并 + Counter 统计 | 可重复运行，结果确定 |
| v2 Agent 版 | 扣子 Coze 三节点工作流（LLM 提取 → 代码聚合 → 报告生成） | 见 `多Agent工作流设计-Coze-Dify.md` |

**交叉验证**：另写 n-gram（2-6 字滑窗）文档频率校验脚本独立复核人工词典的完整性，捕捉到词典遗漏的"消费电子"（4/4 岗位共性词）——人工规则需要算法兜底。

**验收标准**：v2 与 v1 的 Top10 关键词语义重合 ≥60%；关键数字经人工抽样复核。

## 文件结构

```
├── analyzer.py                  # v1 主脚本：词频统计 + 简历覆盖诊断
├── jd_keyword_analysis.py       # 分方向关键词侧重分析
├── jd_crosscheck.py             # n-gram 交叉验证脚本
├── data/jd_corpus.md            # JD 语料（结构化画像）
├── JD关键词匹配报告-v1.md        # v1 产出：Top25 词频 + 缺口清单
├── JD关键词匹配报告-Coze版.md    # v2 产出（Agent 工作流复现）
└── 多Agent工作流设计-Coze-Dify.md # 三节点工作流设计文档（含 Prompt 与评测方案）
```

## 运行方式

```bash
python3 analyzer.py
```

零第三方依赖（仅 Python 标准库），语料在 `data/jd_corpus.md`，可直接替换为自己的 JD 语料。

## 核心产出

- Top 25 高频关键词 + 岗位覆盖矩阵（如"沟通协调能力"覆盖 7/8 个岗位）
- 分方向关键词侧重（GTM 重供应链、FAE 重技术背景、KOL 运营重社媒……）
- 简历缺口分级清单（P0/P1/P2）+ 逐条可落地的修改建议
- 分类统计：通用素质 35% / 市场营销 28% / 销售商务 26% / 技术数据 9%

## 边界说明

- 语料为静态快照，结论需标注数据日期；
- 关键词词典为人工定义，LLM 未参与统计（防幻觉），全部结果可由代码重复计算；
- n-gram 校验与人工词典互为补充，两者不一致处以人工复核为准。
