# JD 词频分析器

> 把"市场要什么 vs 我有什么"变成可复现的数据管道。校招求职者的 JD 批量分析与简历缺口诊断工具。

## 版本历史

| 版本 | 时间 | 关键变化 |
|---|---|---|
| v1（本仓库初版） | 2026-09-08 | 8 份 JD 语料；双实现（Python 脚本 + Coze 三节点 Agent）交叉验证；发现人工词典漏词（n-gram 抓出"消费电子"） |
| v2.0-2.1 | 2026-09-27 | 语料 8→30 份（岗位族标签）；提取层 LLM 化＋人工抽检 ≥20% 冻结；匹配分引入市场常见度加权 |
| v2.2（当前） | 2026-09-28/29 | 语料 30→54 份（分层配额补采，每公司 ≤3）；**匹配层定位重构：撤"投/不投"判决 → 观测性差距清单**；公司级双口径；报告口径全部改为从数据动态生成 |

**为什么要撤掉匹配分的"投/不投"判决？** v2.1 曾按覆盖率把部分岗位定档"谨慎/不投"——随后这些公司实际发出了面试，判决被经验证伪。根因是两个测量被混用：综合适配度（战略判断）≠ 简历词面覆盖率（文本指标），且同义不同词（"技术答疑" vs "技术汇报"）的语义缺口词面匹配看不见。v2.2 起本工具只做它可靠的事：**量化词面差距、生成缺失词清单**；投递决策回归人工的多维评估。这个教训本身是本项目最有价值的产出之一。

## 核心设计决策

**能用代码的环节绝不上模型。** 词频统计是确定性任务，LLM 计数会产生幻觉——因此统计与匹配全部放在 Python（标准库、零依赖），LLM 只做它擅长的"非结构化→结构化"提取，且提取结果**人工抽检后冻结**为数据文件（每条带 provenance，可审计）。同样的数据跑同样的代码，必须得到同样的榜。

**加权匹配，抵抗专名稀释。** 行业专名（安防/测绘/物流）人人都不覆盖，直接算覆盖率会把分数压到无意义。匹配分按"市场常见度"加权：关键词权重 = 其在语料中出现的岗位数——市场高频要求（沟通/逻辑/学习能力）高权重，专名低权重。

**构成偏差显式声明。** 语料为分层配额便利样本（每公司 ≤3 份），频次排序受语料构成影响；解读以"某素质在某族 JD 中**是否被要求**（存在性）"为主、频次排序为辅；岗位级/公司级双口径并列，结论冲突即构成敏感。

## 流水线

| 层 | 实现 | LLM 参与 | 说明 |
|---|---|---|---|
| 语料层 | `data/jd_corpus_v2-part1/2/3.md`（54 份逐字 JD，按编号分三卷） | 无 | 公开招聘页逐字转录，规则：不收转述 |
| 提取层 | `data/keywords_frozen_v2.json` | **有**（人工抽检 ≥20% 后冻结） | 规则：2-8 字、只提取原文、不推测；每条带 provenance |
| 统计层 | `analyze_v2.py` → `词频分析-v2-报告.md` | **零** | 同义词合并 34 组映射全显式；报告口径动态生成 |
| 匹配层 | `match_v2.py` → `单岗匹配分-v2.md` | **零** | 加权覆盖率＋相对分层＋缺失词差距清单 |

岗位族：A-方案/技术支持 ｜ B-AI产品/运营 ｜ C-销售/BD ｜ D-GTM/营销 ｜ X-研发对照（不进主统计，防污染词频）

## 使用

```bash
python3 analyze_v2.py   # 词频统计 → 词频分析-v2-报告.md（脚本同目录）
python3 match_v2.py     # 单岗匹配分 → 单岗匹配分-v2.md
```

零第三方依赖，仅需 Python 3 标准库。换自己的数据：编辑 `data/jd_corpus_v2-part*.md`（按块添加 JD）与 `data/keywords_frozen_v2.json`（按提取规则补充关键词；把 `resume_profiles` 换成你自己的简历可实证词表），重跑两个脚本即可。

## 交付物

| 文件 | 说明 |
|---|---|
| `analyze_v2.py` / `match_v2.py` | 统计层与匹配层（零 LLM，可复现） |
| `data/jd_corpus_v2-part1/2/3.md` | 54 份逐字 JD 语料，按 JD 编号分三卷（岗位族标签＋来源标注） |
| `data/keywords_frozen_v2.json` | 冻结关键词数据（provenance 可审计；resume_profiles 为**示例画像**） |
| `词频分析-v2-报告.md` | 总榜 / 跨族共性词 / 分族 Top |
| `单岗匹配分-v2-DEMO.md` | 示例画像跑出的匹配分报告（展示输出形态；B 画像故意缺 SQL 以演示差距清单） |
| v1 遗产 | `analyzer.py`、`jd_crosscheck.py`、`JD关键词匹配报告-v1.md` 等保留于仓库，见 git 历史 |

目标岗位素质清单（战略层：素质×个人画像映射＋缺口分级）为个人求职文档，不入库——生成方法：以词频报告的跨族共性词为骨架，逐条对照个人简历证据人工分级。

## 隐私与数据声明

- 语料 JD 均转录自公开招聘页面（Boss直聘/企业官网），仅用于求职研究；如有侵权请联系删除。
- 公司名为真实投递目标，属公开招聘信息范畴；语料按公司分层配额采集以控制构成偏差。
- `resume_profiles` 为示例画像（demo data），不含任何真实个人信息。
